# Codex IDE Local Fixes

Локальные исправления официального расширения Codex для VS Code.

1. **История по рабочей папке.** Главный список, меню истории и поиск показывают
   чаты с точным совпадением рабочей папки. В workspace с несколькими корнями
   используются все открытые корни. Чаты из вложенных папок отдельно не включаются.
   Облачные чаты и чаты других execution hosts скрываются в окне с открытой папкой.
   В окне без папки остаётся общий список.
2. **Восстановление интерфейса.** При таймауте запуска через 30 секунд выполняется
   одна повторная загрузка панели. При повторном таймауте появляется страница
   с кнопками перезапуска панели и перезагрузки текущего окна. Из палитры доступна
   команда **Codex: Reload Codex UI (Local Fix)**.
3. **Ранние диагностические сообщения.** В Output → Codex появляются записи
   `Local webview bootstrap` и `Local webview recovery`. Фиксируются этап загрузки,
   время, имя JS/CSS-ресурса и класс ошибки. Тексты чатов, URL, значения секретов
   и стеки в эти дополнительные сообщения не включаются.

Это отдельный установщик патчей, а не форк исходников Codex. IDE-расширение
[не является open source](https://learn.chatgpt.com/docs/open-source).
Установщик работает с уже установленной официальной копией. Бандлы, бинарники
расширения, резервные копии и пользовательские логи в репозиторий не входят.

## Установка

Нужны установленное официальное расширение `openai.chatgpt`, Python 3.9+,
Node.js 18+ и Git. Для приватного репозитория нужен доступ к этому GitHub-аккаунту.

```sh
gh repo clone hammersmithg1/codex-ide-local-fixes
cd codex-ide-local-fixes
python3 install.py --check
python3 install.py
```

В Windows вместо `python3` можно использовать `py -3`.
После установки выполните **Developer: Reload Window** в палитре VS Code.

Автопоиск проверяет папки расширений VS Code, VS Code Insiders, Cursor,
Windsurf и VS Code Remote. Если найдено несколько копий, укажите нужную:

```sh
python3 install.py --extension-dir "/path/to/openai.chatgpt-VERSION-PLATFORM"
```

Для SSH/контейнера установщик нужно запускать на той машине, где расширение
фактически установлено. Самостоятельно подключаться к другим машинам он не будет.

## Совместимость и обновления

Поддерживается версия **26.1021.22027** с ожидаемой структурой JavaScript-бандлов.
Проверено на macOS arm64. Поиск путей предусмотрен для macOS/Linux/Windows,
но интерфейс расширения на Linux/Windows пока не проверен.

Установщик проверяет версию, точные места изменений и синтаксис JavaScript.
При несовпадении он останавливается до записи файлов. Оригиналы сохраняются в
`~/.agents/local/backups/codex-ide-local-fixes/`. Ошибка записи вызывает откат
уже записанных файлов. Повторный запуск проверяет установленную копию.

Обновление официального расширения может заменить исправленные файлы.
Для другой версии потребуется адаптировать патч; автоматическая совместимость
с неизвестными версиями не предполагается. Автообновления установщик не отключает.

## Если панель снова зависла

Сначала выполните **Codex: Reload Codex UI (Local Fix)**. Команда обновляет
интерфейс и его IPC-сессию, не перезапуская app-server или все окна VS Code.
Несохранённый черновик ввода в перезагружаемой панели может потеряться.

При неудаче используйте кнопку перезагрузки текущего окна на странице восстановления.
Для просмотра только диагностических записей:

```sh
python3 install.py --diagnose
```

Автопоиск логов этой команды рассчитан на обычный VS Code. Для Cursor/Insiders/Remote
используйте Output → Codex или **Developer: Open Logs Folder** в соответствующем редакторе.

В доступных логах исходной машины были таймауты `renderer_ready_timeout` с
`receivedWebviewMessage=false` до добавления фильтра истории. При этом app-server
продолжал обрабатывать текущий разговор. Существующие логи не устанавливают,
почему webview перестал запускаться. Патч добавляет восстановление и наблюдаемость;
устранение первопричины зависания Chromium/webview пока не подтверждено.

## Откат

```sh
python3 install.py --restore
```

Затем выполните **Developer: Reload Window**. Откат проверяет контрольные суммы
и отказывается перезаписывать файлы, изменившиеся после установки. На исходном
компьютере проверенная резервная копия предыдущего фильтра истории переносится
в новый механизм отката, поэтому восстанавливается оригинальное расширение.

## Проверки

```sh
python3 -m unittest discover -s tests -v
node tests/history.cjs
node tests/recovery.cjs
python3 install.py --check
```

Проверки покрывают точное сопоставление папок, переключение workspace, ограничение
повторов, уничтожение webview во время загрузки, повторные нажатия, ранний bootstrap,
откат, проверку резервных копий и восстановление после ошибки записи.

Шаблон `examples/test-workflow.yml` рассчитан на GitHub Actions с macOS, Ubuntu
и Windows. Автозапуск не включён: для добавления файла в `.github/workflows/`
нужно право GitHub `workflow`. Это проверки установщика и логики; они не запускают
настоящее расширение в GUI.

Для дополнительной локальной проверки настоящего бандла истории передайте путь
к подготовленному пропатченному файлу через `CODEX_TEST_HISTORY_PREVIEW` при запуске
`node tests/history.cjs`. Проприетарный файл остаётся вне репозитория.

Для проверки настоящего метода `initializeWebview` задайте
`CODEX_TEST_EXTENSION_PREVIEW` с путём к подготовленному `extension.js` и запустите
`node tests/host_integration.cjs`. Проверяется цепочка: таймаут → автоповтор →
страница восстановления → ручной повтор → готовность → закрытие webview.
